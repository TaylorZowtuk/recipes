# Backend

- Python is pinned in `.python-version` to the newest version the Lambda runtime supports.
- Ruff runs with every rule on (`select = ["ALL"]`) and pyright in strict mode. Add an ignore to `pyproject.toml` with a reason rather than scattering `noqa`.
- Tests drive the API over HTTP with FastAPI's `TestClient` and fake AWS with moto. They never touch a real stack.
- Signing in locally: under `make dev` and the local e2e tests (`recipes.local`), the editor is `editor@example.com`, a Google credential is `fake:<email>` (`fake-unverified:<email>` for an unverified one), and the service token is `local-dev-service-token` in the `x-plateful-service-token` header. Tests inject their own settings and a fake verifier through `create_app(auth=...)`.
- Ingesting locally: under `make dev` and the local e2e tests, the fake web serves a synthetic recipe at `https://plateful.test/<slug>`, titled after the slug, and `/missing/…`, `/blocked/…`, `/robots-denied/…` and `/no-recipe/…` give each failure. A recipe page's candidate photos are generated placeholders under `/photos/`, which `POST /api/images` stores in moto's images bucket, served at `/images/*` by the dev apps only (`recipes.local`, and `recipes.staging` under `make dev STAGING_PROFILE=…`), never by Lambda's `recipes.api`, and the seed gives most recipes a placeholder photo. Every other host is unreachable. Each Source can be ingested once on the shared server, so a test takes a fresh path. Unit tests fetch through `FakeWeb` in `tests/fake_web.py`, whose resolver puts every named host on a public address.
- Enriching takes two passes. `python -m recipes.enrich substitutes <API base URL>` prints a Substitutes Packet of every Pending recipe and writes nothing; a model answers it with the substitutes file, quoting each substitute the recipe itself states. `python -m recipes.enrich packet <API base URL> --substitutes <file>` checks every quote is in the line, step or description it names, then prints a Work Packet of every Pending recipe, offering candidates for each quote, and writes nothing (a bad quote prints every error and no packet); a model answers it, and `python -m recipes.enrich apply <API base URL> <answer file, or - for stdin> --substitutes <the same file>` checks the answer against the packet (rebuilt from the API and the file) and writes each recipe whose offer hasn't changed since (each recipe's `offer_id`, which its answer echoes) and whose answer chose only what it was offered. Without `--substitutes`, nothing is offered as a substitute. All three send the service token from `PLATEFUL_SERVICE_TOKEN`. Run them from `make shell`: against `make dev`, `PLATEFUL_SERVICE_TOKEN=local-dev-service-token uv run python -m recipes.enrich substitutes http://api:8787 > ask.json`, then `… packet http://api:8787 --substitutes substitutes.json > packet.json`, then `… apply http://api:8787 answer.json --substitutes substitutes.json`; against a stack, its CloudFront URL and service token. The packet and the answer's checks are in `packet.py`; bump `ENRICHMENT_VERSION` there when what enrichment writes changes. Conversions and nutrition come from the committed FDC Snapshot in `backend/fdc/` (`uv run python -m recipes.fdc build` rebuilds it); tests use the synthetic `tests/fixtures/fdc-snapshot.json`. The parser's NLTK tagger is fetched once into the shared cache (`$NLTK_DATA`) by `make check` and `make shell`, so it runs offline afterwards. Nothing else fetches it: the API never imports the parser, and the release build leaves it out.
- After changing an endpoint or its models, run `make api-client` and commit the regenerated client.
