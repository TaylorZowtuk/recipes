# Backend

- Python is pinned in `.python-version` to the newest version the Lambda runtime supports.
- Ruff runs with every rule on (`select = ["ALL"]`) and pyright in strict mode. Add an ignore to `pyproject.toml` with a reason rather than scattering `noqa`.
- Tests drive the API over HTTP with FastAPI's `TestClient` and fake AWS with moto. They never touch a real stack.
- Signing in locally: under `make dev` and the local e2e tests (`recipes.local`), the editor is `editor@example.com`, a Google credential is `fake:<email>` (`fake-unverified:<email>` for an unverified one), and the service token is `local-dev-service-token` in the `x-plateful-service-token` header. Tests inject their own settings and a fake verifier through `create_app(auth=...)`.
- Ingesting locally: under `make dev` and the local e2e tests, the fake web serves a synthetic recipe at `https://plateful.test/<slug>`, titled after the slug, and `/missing/…`, `/blocked/…`, `/robots-denied/…` and `/no-recipe/…` give each failure. A recipe page's candidate photos are generated placeholders under `/photos/`, which `POST /api/images` stores in moto's images bucket, served at `/images/*` by the dev apps only (`recipes.local`, and `recipes.staging` under `make dev STAGING_PROFILE=…`), never by Lambda's `recipes.api`, and the seed gives most recipes a placeholder photo. Every other host is unreachable. Each Source can be ingested once on the shared server, so a test takes a fresh path. Unit tests fetch through `FakeWeb` in `tests/fake_web.py`, whose resolver puts every named host on a public address.
- Enriching takes two passes. `python -m recipes.enrich substitutes <API base URL>` prints a Substitutes Packet of every Pending recipe and writes nothing, without the FDC Snapshot; a model answers it with the substitutes file, quoting each substitute the recipe itself states. `python -m recipes.enrich packet <API base URL> --substitutes <file>` checks every quote is in the place it names (the line itself, a step or the description), ignoring case and on word boundaries, skipping a recipe that is no longer Pending, then prints a Work Packet of every Pending recipe, offering candidates for each quote, and writes nothing (a bad quote prints every error and no packet); a model answers it, and `python -m recipes.enrich apply <API base URL> <answer file, or - for stdin> --substitutes <the same file>` checks the answer against the packet (rebuilt from the API and the file) and writes each recipe whose offer hasn't changed since (each recipe's `offer_id`, which its answer echoes) and whose answer chose only what it was offered, printing each written recipe's Enrichment Issues under it. Without `--substitutes`, nothing is offered as a substitute. All three send the service token from `PLATEFUL_SERVICE_TOKEN`. Run them from `make shell`: against `make dev`, `PLATEFUL_SERVICE_TOKEN=local-dev-service-token uv run python -m recipes.enrich substitutes http://api:8787 > ask.json`, then `… packet http://api:8787 --substitutes substitutes.json > packet.json`, then `… apply http://api:8787 answer.json --substitutes substitutes.json`; against a stack, its CloudFront URL and service token. Or run each from the host with `make enrich ARGS='…'`, `PLATEFUL_SERVICE_TOKEN` exported in your environment, file arguments relative to `backend/`: `make enrich ARGS='substitutes http://api:8787' > backend/ask.json`, and `apply`'s `-` reads the answer piped into `make enrich`. The Substitutes Packet and the substitutes file's checks are in `substitutes.py`, the Work Packet and the answer's checks in `packet.py`; bump `ENRICHMENT_VERSION` there when what enrichment writes changes. Conversions and nutrition come from the committed FDC Snapshot in `src/recipes/data/` (`uv run python -m recipes.fdc build` rebuilds it), which ships in the Lambda zip so the API can search it and turn an editor's pick into numbers; the API loads it on first use, never at import; tests use the synthetic `tests/fixtures/fdc-snapshot.json`. The parser's NLTK tagger is fetched once into the shared cache (`$NLTK_DATA`) by `make check` and `make shell`, so it runs offline afterwards. Nothing else fetches it: the API never imports the parser, and the release build leaves it out.
- Running the ingest fallback takes two commands, run from `backend/` in `make shell`, or from the host with `make fallback ARGS='…'` (file arguments relative to `backend/`), with `PLATEFUL_SERVICE_TOKEN` set to the stack's service token. `python -m recipes.fallback run <API base URL> > packet.json` takes each waiting website Queued Ingest through a browser, then recipe-scrapers on the loaded page, saves what they read, marks pages nothing can read as needing their page, and prints a Work Packet of the pages left for a model to stdout. A fetch that fails as `rate_limited`, `server_error` or `unreachable` records that reason on the Queued Ingest (`POST /api/queued-ingests/{id}/failed-attempt`), which stays waiting for the next `run`, and the summary counts it as still waiting, not failed, so it doesn't change the exit code. A 404 or 410 still goes to needs-page. A model answers it, and `python -m recipes.fallback apply <API base URL> packet.json <answer file, or - for stdin>` checks each answer against the packet word for word and saves it with the extractor `llm`, or marks the Queued Ingest as needing its page. The packets hold recipe or page text, so never commit them: `backend/packet.json`, `backend/answer.json`, `backend/ask.json` and `backend/substitutes.json` are gitignored, so keep to those names. The bulk import shares the module's `capture`.
- Pulling a backup: `python -m recipes.backup pull <API base URL> --to <folder>`, with `PLATEFUL_SERVICE_TOKEN` set, or from the host `make backup ARGS='pull <stack URL> --to backups'` (relative to `backend/`; `backend/backups/` is gitignored, since it holds the whole Collection). It asks `GET /api/backup/links` (editors only) for 15-minute presigned links into the backup bucket, then downloads with a plain session that never sends the token: the latest Backup Snapshot and each image not already in the folder, each at its key under the folder, through a part file renamed into place. Under `make dev` the backup bucket is moto's, inside the API process, so the links list nothing and can't be downloaded from outside it.
- After changing an endpoint or its models, run `make api-client` and commit the regenerated client.
